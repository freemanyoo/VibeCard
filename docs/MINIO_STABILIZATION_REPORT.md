# MinIO 스토리지 연동 및 이미지 업로드 안정화 리포트

본 문서는 시놀로지 상용 환경에서 발생한 MinIO 연동 이슈와 사진 업로드 속도 저하 문제를 해결하고 안정화한 과정을 기록합니다.

---

## 1. 주요 발생 문제 (Issues)

### 1.1 MinIO 연동 및 권한 문제
*   **환경 변수 매핑 누락**: `.env.prod`에 정의된 MinIO 설정값이 백엔드의 `application.yml`을 통해 내부 프로퍼티로 전달되지 않아 스토리지 기능이 정상 작동하지 않았습니다.
*   **버킷 접근 권한(Policy) 부재**: 이미지 업로드에는 성공하더라도, 외부(프론트엔드)에서 URL을 통해 이미지를 읽어오려 할 때 권한 오류(Access Denied)가 발생했습니다.

### 1.2 업로드 성능 병목 현상
*   **네트워크 전송 부하**: 모바일 기기로 촬영한 20MB 이상의 고용량 사진이 그대로 서버로 전송되느라 네트워크 대기 시간이 매우 길었습니다.
*   **서버 처리 지연**: 서버 내부에서 사진을 한 장 받을 때마다 순차적으로 '원본 최적화 -> 썸네일 생성 -> AI 분석용 이미지 생성' 과정을 거쳤으며, 매 단계마다 미니오 서버와 통신하며 권한을 확인하는 오버헤드가 발생했습니다.

---

## 2. 해결 및 안정화 방안 (Solutions)

### 2.1 스토리지 안정화 (Backend)
*   **설정 매핑**: `application.yml`에 환경 변수를 명시적으로 매핑하여 스토리지 설정을 활성화했습니다.
*   **자동 권한 부여(Public Read)**: `ObjectStorageService`에서 파일이 저장될 버킷을 확인할 때, 자동으로 `s3:GetObject` 권한을 공개(Principal: *)로 설정하는 Policy를 주입하도록 개선했습니다.
*   **설정 캐싱**: 한 번 확인된 버킷의 준비 상태를 서버 메모리에 저장하여, 이후 업로드 시 중복된 권한 체크 과정을 생략했습니다.

### 2.2 업로드 성능 최적화 (Full-Stack)

#### [Frontend] 클라이언트 사이드 압축 & 즉시 미리보기
*   **이미지 압축**: 브라우저에서 `Canvas API`를 사용하여 업로드 전 이미지를 약 1~2MB 수준으로 리사이징 및 압축합니다. 이로 인해 실제 전송되는 데이터 양이 1/10 이하로 줄어들었습니다.
*   **Optimistic UI (선행 시각화)**: `URL.createObjectURL`을 사용하여 업로드 버튼을 누르는 즉시 화면에 사진을 띄운 뒤, 배경에서 업로드를 진행합니다. 사용자 입장에서는 지연 시간이 '0'인 것처럼 느끼게 됩니다.

#### [Backend] 병렬 처리 도입
*   **CompletableFuture 적용**: 서버가 파일을 받은 후 수행하는 3종의 이미지 처리 및 저장 작업을 비동기 병렬 방식으로 변경했습니다. 세 가지 작업이 동시에 진행되므로 전체 응답 속도가 대폭 향상되었습니다.

---

## 3. 적용 결과 (Outcome)

*   **가용성**: 상용 환경에서 MinIO를 통한 이미지 저장 및 외부 노출이 100% 정상 작동합니다.
*   **속도**: 20MB 대용량 사진 업로드 시 기존 수십 초 소요되던 체감 시간이 **즉시 반영** 수준으로 개선되었습니다.
*   **안정성**: 서버 부하를 줄이면서도 데이터 유실 없이 안정적인 서비스 운영이 가능해졌습니다.
