# Use Case

현재 VibeCard 시스템 기준 핵심 유스케이스 문서입니다.

## 1. 액터

- 비회원 방문자
- 회원 사용자
- 관리자
- AI 서비스
- 소셜 로그인 제공자

## 2. 시스템 목적

사용자가 모바일 청첩장을 생성, 수정, 공유하고, 하객 응답과 방명록을 수집하며, AI를 이용해 스킨/디자인 초안을 보조 생성할 수 있게 하는 것입니다.

## 3. 핵심 유스케이스 목록

### UC-01. 회원가입

- 액터: 비회원 방문자
- 설명: 이메일 또는 소셜 계정으로 회원 계정을 생성한다.
- 선행조건: 해당 이메일 또는 소셜 계정이 기존 사용자와 중복되지 않아야 한다.
- 기본 흐름:
  1. 사용자가 회원가입 화면에 진입한다.
  2. 이메일/비밀번호 또는 소셜 로그인 방식을 선택한다.
  3. 시스템이 입력값을 검증한다.
  4. 시스템이 사용자 계정을 생성한다.
  5. 회원가입 완료 메시지를 보여준다.
- 결과:
  - `users` 데이터 생성

### UC-02. 로그인

- 액터: 회원 사용자
- 설명: 사용자가 이메일/비밀번호 또는 소셜 로그인으로 로그인한다.
- 선행조건: 등록된 계정이어야 한다.
- 기본 흐름:
  1. 사용자가 로그인 정보를 입력한다.
  2. 시스템이 계정을 검증한다.
  3. 시스템이 액세스 토큰/리프레시 토큰을 발급한다.
  4. 사용자를 대시보드로 이동시킨다.
- 결과:
  - 인증 세션 시작
  - `refresh_tokens` 갱신

### UC-03. 내 청첩장 목록 조회

- 액터: 회원 사용자
- 설명: 사용자가 자신이 만든 청첩장 목록을 조회한다.
- 선행조건: 로그인 상태여야 한다.
- 기본 흐름:
  1. 사용자가 대시보드에 진입한다.
  2. 시스템이 해당 사용자의 청첩장 목록을 조회한다.
  3. 시스템이 각 청첩장 제목, 슬러그, 대표 이미지, 생성일 등을 표시한다.
- 결과:
  - `invitation` 목록 조회

### UC-04. 청첩장 생성

- 액터: 회원 사용자
- 설명: 사용자가 새 청첩장을 생성한다.
- 선행조건: 로그인 상태여야 한다.
- 기본 흐름:
  1. 사용자가 청첩장 만들기 화면에 진입한다.
  2. 기본 정보, 예식 정보, 스킨, 대표 이미지 등을 입력한다.
  3. 시스템이 slug 중복 여부를 확인한다.
  4. 시스템이 청첩장을 저장한다.
- 결과:
  - `invitation` 생성

### UC-05. 청첩장 수정

- 액터: 회원 사용자
- 설명: 사용자가 기존 청첩장을 수정한다.
- 선행조건: 본인 소유 청첩장이어야 한다.
- 기본 흐름:
  1. 사용자가 청첩장 편집기에 진입한다.
  2. 텍스트, 이미지, 색상, 배치, 계좌정보 등을 수정한다.
  3. 시스템이 수정값을 저장한다.
- 결과:
  - `invitation.config`
  - `invitation` 주요 속성
  - 연관 `bank_account`
  - 연관 갤러리 데이터
  가 갱신된다.

### UC-06. 청첩장 삭제

- 액터: 회원 사용자
- 설명: 사용자가 본인 청첩장을 삭제한다.
- 선행조건: 본인 소유 청첩장이어야 한다.
- 기본 흐름:
  1. 사용자가 삭제 버튼을 누른다.
  2. 시스템이 본인 소유 여부를 검증한다.
  3. 시스템이 삭제를 수행한다.
- 결과:
  - `invitation` 삭제
  - 연관 `bank_account`, `attendance`, `guestbook` 정리

### UC-07. 청첩장 공개 조회

- 액터: 비회원 방문자, 회원 사용자
- 설명: 사용자가 공유 링크로 청첩장을 조회한다.
- 선행조건: 유효한 slug여야 한다.
- 기본 흐름:
  1. 사용자가 청첩장 URL에 접속한다.
  2. 시스템이 slug로 청첩장을 조회한다.
  3. 시스템이 청첩장 본문, 이미지, 위치, 계좌, 참석 폼 등을 렌더링한다.
- 결과:
  - 공개 청첩장 열람

### UC-08. 하객 참석 여부 제출

- 액터: 비회원 방문자, 회원 사용자
- 설명: 하객이 참석 여부를 남긴다.
- 선행조건: 해당 청첩장이 응답을 받는 상태여야 한다.
- 기본 흐름:
  1. 하객이 성함, 참석 여부, 식사 여부 등을 입력한다.
  2. 시스템이 입력값을 검증한다.
  3. 시스템이 응답을 저장한다.
- 결과:
  - `attendance` 생성

### UC-09. 방명록 작성

- 액터: 비회원 방문자, 회원 사용자
- 설명: 하객이 축하 메시지를 남긴다.
- 선행조건: 방명록 기능이 활성화되어 있어야 한다.
- 기본 흐름:
  1. 하객이 작성자명과 메시지를 입력한다.
  2. 시스템이 메시지를 저장한다.
  3. 시스템이 방명록 목록에 반영한다.
- 결과:
  - `guestbook` 생성

### UC-10. 계좌 정보 조회/복사

- 액터: 비회원 방문자, 회원 사용자
- 설명: 하객이 축의금 계좌 정보를 확인하고 복사한다.
- 선행조건: 계좌 정보가 등록되어 있어야 한다.
- 기본 흐름:
  1. 사용자가 신랑측/신부측 계좌 보기를 누른다.
  2. 시스템이 계좌 정보를 표시한다.
  3. 사용자가 계좌번호를 복사한다.
- 결과:
  - 저장 데이터 변경 없음
  - `bank_account` 조회

### UC-11. 스킨 목록 조회

- 액터: 회원 사용자, 관리자
- 설명: 사용자가 청첩장에 적용 가능한 스킨 목록을 조회한다.
- 기본 흐름:
  1. 사용자가 스킨 라이브러리에 진입한다.
  2. 시스템이 활성 스킨 목록을 보여준다.
- 결과:
  - `skin` 조회

### UC-12. AI 스킨 생성

- 액터: 회원 사용자
- 설명: 사용자가 프롬프트를 입력해 AI로 스킨 초안을 생성한다.
- 선행조건: 로그인 상태, AI 기능 사용 가능 상태여야 한다.
- 기본 흐름:
  1. 사용자가 원하는 스타일을 명령어로 입력한다.
  2. 시스템이 선택한 AI 모델에 요청한다.
  3. AI 서비스가 스킨 설정 초안을 반환한다.
  4. 시스템이 결과를 편집기에 반영한다.
  5. 시스템이 생성 이력을 저장한다.
- 결과:
  - `ai_generation_history` 생성
  - 필요 시 `skin` 또는 `invitation.config` 반영

### UC-13. AI 이미지 기반 디자인 생성

- 액터: 회원 사용자
- 설명: 사용자가 업로드한 이미지를 바탕으로 AI가 어울리는 청첩장 설정을 제안한다.
- 선행조건: 로그인 상태, 이미지 업로드 가능 상태여야 한다.
- 기본 흐름:
  1. 사용자가 이미지를 업로드한다.
  2. 시스템이 원본/썸네일/분석용 이미지를 저장한다.
  3. 시스템이 AI에 이미지 분석 요청을 보낸다.
  4. AI가 분위기/색상/스타일 초안을 반환한다.
  5. 시스템이 결과를 편집기에 반영한다.
  6. 시스템이 생성 이력을 저장한다.
- 결과:
  - `media_files` 생성
  - `ai_generation_history` 생성

### UC-14. 이미지 업로드

- 액터: 회원 사용자
- 설명: 사용자가 청첩장 대표 이미지나 갤러리 이미지를 업로드한다.
- 선행조건: 로그인 상태여야 한다.
- 기본 흐름:
  1. 사용자가 이미지를 선택한다.
  2. 시스템이 파일을 저장한다.
  3. 시스템이 썸네일/분석용 이미지를 생성한다.
  4. 시스템이 메타데이터를 저장한다.
- 결과:
  - `media_files` 생성

### UC-15. 관리자 스킨 관리

- 액터: 관리자
- 설명: 관리자가 스킨을 생성, 수정, 비활성화, 삭제한다.
- 선행조건: 관리자 권한이 있어야 한다.
- 기본 흐름:
  1. 관리자가 관리자 페이지에 진입한다.
  2. 스킨 정보를 입력하거나 수정한다.
  3. 시스템이 저장한다.
- 결과:
  - `skin` 생성/수정/비활성화

### UC-16. 악성 프롬프트 차단 기록

- 액터: 회원 사용자, 관리자, AI 서비스
- 설명: 사용자가 정책 위반 프롬프트를 보냈을 때 차단하고 기록한다.
- 기본 흐름:
  1. 사용자가 AI 요청을 보낸다.
  2. 시스템이 프롬프트를 검사한다.
  3. 정책 위반이면 요청을 차단한다.
  4. 시스템이 차단 사유와 프롬프트를 저장한다.
- 결과:
  - `ai_prompt_block_logs` 생성

## 4. 유스케이스 관계 요약

- 회원가입 후 로그인 가능
- 로그인 후 청첩장 생성/수정/삭제 가능
- 청첩장 생성 후 공개 조회 가능
- 공개 조회 중 참석 응답/방명록 작성 가능
- 이미지 업로드 후 AI 이미지 기반 생성 가능
- AI 스킨 생성/AI 이미지 기반 생성 결과는 청첩장 편집기로 연결됨

## 5. DB 기준 매핑

- 사용자 계정: `users`
- 로그인 유지: `refresh_tokens`
- 청첩장 본체: `invitation`
- 계좌 정보: `bank_account`
- 참석 응답: `attendance`
- 방명록: `guestbook`
- 스킨 라이브러리: `skin`
- 업로드 이미지 메타데이터: `media_files`
- AI 생성 이력: `ai_generation_history`
- AI 차단 로그: `ai_prompt_block_logs`
